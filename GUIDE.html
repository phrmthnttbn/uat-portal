01 — ติดตั้งและอัปเดตบน Windows

A. เปิดโปรเจกต์ใหม่จาก ZIP

1. ติดตั้ง Node.js 22 LTS, Git for Windows และ VS Code หากยังไม่มี

2. คลิกขวา ZIP → Extract All ให้ได้โฟลเดอร์ uat-portal-management

3. อย่าเปิดงานภายใน ZIP ให้แตกไฟล์ก่อน

4. เปิด VS Code → File → Open Folder → เลือกโฟลเดอร์ที่มี package.json

5. เลือก Terminal → New Terminal ตรวจว่าอยู่โฟลเดอร์โปรเจกต์

6. รันคำสั่งทีละบรรทัด:

npm ci
npm run dev

7. เปิด URL ที่ Terminal แสดง ปกติ http://127.0.0.1:5173/

8. ลองสลับ Project ด้านบน ระหว่าง RIDER กับ PORTAL ต้องเห็นข้อมูลต่างกัน

9. หยุด server ด้วย Ctrl+C

หาก PowerShell ไม่อนุญาต npm.ps1 ใช้ npm.cmd แทน npm ทุกคำสั่ง ไม่ต้องเปลี่ยน Execution Policy

B. อัปเดต repository เดิมโดยเก็บประวัติ Git

1. ก่อนอัปเดต ให้เปิดเว็บเดิมแล้ว Export ข้อมูลที่ต้องเก็บไว้ เก็บ ZIP/source เดิมสำรองด้วย

2. แตก ZIP ใหม่นอก repository เดิมเพื่อป้องกันโฟลเดอร์ซ้อน

3. เปิด repository เดิมใน VS Code ตรวจการแก้ที่ค้างอยู่ก่อน:

git status
git branch --show-current

4. ถ้ามีงานที่ยังไม่บันทึก ให้ commit งานเดิมหรือสำรองก่อน แล้วสลับ develop:

git switch develop
git pull --ff-only origin develop

5. คัดลอกไฟล์ต่อไปนี้จาก ZIP ไปยังตำแหน่งชื่อเดียวกันใน repository เดิม:

- src/main.tsx และ src/model.ts

- src/style.css

- index.html

- package.json และ package-lock.json (ต้องคัดลอกเป็นคู่)

- tests/ ทั้งโฟลเดอร์

- docs/ ทั้งโฟลเดอร์

- public/samples/ ทั้งโฟลเดอร์

- .github/workflows/deploy.yml

- .prettierrc.json และ .prettierignore

- README.md และ BUILD-VERIFICATION.md

6. คงไฟล์ vite.config.ts, tsconfig.json, tailwind.config.js และ postcss.config.js เดิมได้หากยังเหมือนเวอร์ชันเริ่มต้น ถ้าแก้เองให้เทียบกับ ZIP ก่อน

7. ห้ามลบหรือแทนที่ .git และไม่ต้องคัดลอก node_modules หรือ dist

8. src/data.ts เก่า, ProjectManager.tsx หรือ auth.ts ที่เคยสร้างไว้ไม่ถูกใช้ใน entry ใหม่ จะเก็บไว้ก่อนได้

9. ติดตั้งและตรวจ:

npm ci
npm run format:check
npm test
npm run build
npm run dev

10. หน้าจอแสดง UAT Portal Management v2 และเมนู Projects / Data & Backup ข้อมูลเริ่มต้นใหม่เป็นปกติ เพราะแยกจาก localStorage รุ่นเดิม

11. ทดลองตาม docs/05-ACCEPTANCE-CHECKLIST.md ก่อนส่งขึ้น GitHub

C. ปัญหาที่พบบ่อย

- ENOENT package.json: เปิด Terminal ผิดโฟลเดอร์ ให้เข้าโฟลเดอร์ที่มี package.json

- npm ci ล้มเหลวเพราะ lockfile: ตรวจว่าคัดลอก package.json และ package-lock.json จาก ZIP ชุดเดียวกัน

- Port ถูกใช้: ใช้ URL ใหม่ที่ Vite แสดง ไม่ยึด 5173 เสมอ

- ไม่เห็นข้อมูลเดิม: v2 เริ่ม storage ใหม่ ข้อมูลเก่าไม่ถูกแปลงอัตโนมัติ

- บันทึกไม่สำเร็จ: browser อาจปิด localStorage หรือพื้นที่เต็ม Backup ข้อมูลก่อนล้าง browser

- เปิด index.html แล้วหน้าขาว: ต้องใช้ npm run dev หรือ npm run preview ไม่ใช้ file://

02 — คู่มือใช้งานทุกหน้าจอ

1. Project

เปิด Projects → เพิ่มโครงการ → กรอกรหัสและชื่อ → บันทึก รหัสต้องไม่ซ้ำทั้งระบบ เลือกเปิดโครงการหรือเลือกจากตัวเลือกด้านบน ทุกหน้าจอแสดงข้อมูลเฉพาะโครงการที่เลือก

แก้ไขชื่อหรือรายละเอียดได้ เก็บถาวรจะล็อกการแก้ข้อมูลทดสอบ แต่ดูและ Export ได้ นำกลับมาใช้ได้ภายหลัง ไม่ลบโครงการเพื่อรักษาประวัติ หากค้นหาแล้วไม่พบให้ล้างคำค้น

2. Test Scenarios

เลือก Project → Test Scenarios → เพิ่ม Scenario กรอกรหัส ชื่อ รายละเอียด รหัสต้องไม่ซ้ำภายใน Project กดเปิด Test Cases เพื่อกรองรายการของ Scenario นั้น

ลบ Scenario ได้เมื่อไม่มี Case อ้างอิง หากมี Case ต้องย้าย Case ไป Scenario อื่นหรือลบ Case ที่ไม่จำเป็นก่อน

3. Test Cases

สร้าง Scenario ก่อน → เพิ่ม Test Case → ระบุ Scenario, ชื่อ, ขั้นตอน, ผลที่คาดหวัง, Priority และผู้รับผิดชอบ กดบันทึก ค้นหาด้วยรหัส ชื่อ หรือผู้รับผิดชอบ และกรองตามสถานะกับ Scenario ได้

ลบ Case ที่ไม่มี Defect อ้างอิงได้หลังยืนยัน ประวัติผลของ Case นั้นจะถูกลบด้วย Case ที่มี Defect อ้างอิงลบไม่ได้แม้ Defect ปิดแล้ว เพื่อรักษาการเชื่อมโยง แก้ไขข้อมูลแทน

4. Test Results

กดดู / บันทึกผลจาก Test Cases หรือ Test Results อ่าน Steps และ Expected result ก่อนทดสอบ ระบุ Status, Actual result, ผู้ทดสอบ และลิงก์หลักฐานถ้ามี แล้วบันทึก

ทุกครั้งสร้างประวัติใหม่ ไม่เขียนทับผลเดิม เปิดประวัติการทดสอบเพื่อดูย้อนหลัง Dashboard ใช้รายการล่าสุดที่บันทึกของแต่ละ Case

- Passed: ผ่าน

- Failed: ไม่ตรงผลคาดหวัง

- Blocked: ทดสอบต่อไม่ได้

- Not run: คืนสถานะยังไม่ทดสอบ (ต้องกรอกเหตุผลใน Actual result เช่นเดียวกับสถานะอื่น)

หลักฐานรองรับ URL http/https เท่านั้น ไม่มีการอัปโหลดภาพเข้า server เก็บภาพในพื้นที่ที่ทีมใช้แล้วนำลิงก์มาวาง

5. Defect Tracking

Case ที่ Failed มีปุ่มสร้าง Defect ระบบเตรียมชื่อและผลที่พบจริงให้ หรือกดรายงาน Defect ในเมนูโดยตรง ระบุ Case ที่เกี่ยวข้อง ชื่อ วิธีทำให้เกิดปัญหา Severity และ Owner

เปลี่ยนสถานะ Open → In progress → Resolved → Closed หรือเปิดกลับได้ตามการทำงานจริง ระบบไม่บังคับลำดับ ปิด Defect ไม่ทำให้ Case ผ่านอัตโนมัติ ต้อง Retest แล้วบันทึก Passed ด้วย

กดรายละเอียด / Comment เพื่อดูคำอธิบายและเพิ่มความคิดเห็นพร้อมชื่อ แก้รายละเอียดได้ แต่ไม่มีปุ่มลบ Defect เพื่อเก็บประวัติ Comment ไม่มีฟังก์ชันแก้หรือลบ

6. Dashboard

ยอดทั้งหมดมาจาก Project ที่เลือก Execution progress = Case ที่สถานะล่าสุดไม่ใช่ Not run / Case ทั้งหมด Passed, Failed, Blocked เป็นสถานะล่าสุด ไม่นับจำนวนครั้งที่กดทดสอบ

กราฟ Scenario ใช้จำนวน executed ไม่ใช่ pass rate กดเริ่มทดสอบหรือเลือก Project อื่นเพื่อเปลี่ยนขอบเขต Case ที่ยังไม่ผ่านจะปรากฏใน Next to test

7. UAT Sign-off

ต้องมี Case อย่างน้อยหนึ่งรายการ ทุก Case Passed และ Defect ทั้งหมด Closed ก่อนกรอกชื่อผู้รับรองและหมายเหตุ บันทึกแล้วเห็นวันเวลาและสามารถยกเลิกได้

เมื่อเพิ่ม/แก้/ลบ Scenario หรือ Case, บันทึกผลใหม่, เพิ่ม/แก้ Defect หรือเปลี่ยนสถานะ Defect รวมถึง Import ระบบจะล้าง Sign-off ของ Project นั้น ต้องรับรองใหม่หลังตรวจผลครบ การเพิ่ม Comment หรือแก้ชื่อ Project ไม่ล้าง Sign-off

Sign-off เป็นข้อมูลจำลอง ไม่ตรวจตัวตนและไม่ใช่ลายเซ็นดิจิทัล

8. Import / Export CSV

เปิด Data & Backup เลือกประเภท Scenario หรือ Case ดาวน์โหลด Template แล้วแก้ข้อมูลโดยคงหัวตารางเดิม ถ้าใช้ Excel ให้ Save As CSV UTF-8 ก่อนนำเข้า

นำเข้า Scenario ก่อน Case คอลัมน์ scenarioCode ต้องตรงกับรหัส Scenario ในโครงการปัจจุบัน Priority ใช้ Low, Medium, High หรือ Critical เท่านั้น

เลือกไฟล์ → ยืนยัน → ระบบตรวจทั้งไฟล์ก่อนบันทึก หากแถวใดผิดจะไม่เพิ่มข้อมูลเลย รหัสซ้ำจะถูกปฏิเสธ ไม่อัปเดตรายการเดิม จำกัดไฟล์ 5 MB รองรับเครื่องหมาย comma และบรรทัดใหม่เมื่อใช้ CSV ที่ quote ถูกต้อง ไม่รองรับ .xlsx

Template Case ใช้ Scenario แรกของโครงการ ถ้ายังไม่มี Scenario ให้สร้างก่อน หรือเปลี่ยน scenarioCode ให้ตรงหลัง Import Scenario

CSV export มีการเติม apostrophe ให้ค่าเริ่มด้วยเครื่องหมายที่ spreadsheet อาจตีความเป็นสูตร ค่าพิเศษเหล่านี้อาจต้องแก้ก่อนนำกลับเข้า

9. รายงาน / สำรอง / กู้คืน

- Export report ด้านบน: JSON เฉพาะโครงการพร้อม Summary และข้อมูลทดสอบ ใช้อ่าน/ส่งรายงาน ไม่ใช่ไฟล์ Restore

- Backup ทั้งหมด: JSON version 2 ที่รวมทุกโครงการ ใช้ Restore ได้

- Restore: เลือก Backup → ตรวจรูปแบบ → ยืนยันแทนที่ข้อมูลทุกโครงการ จึงต้อง Backup ปัจจุบันก่อน

- ดาวน์โหลดข้อมูลดิบ: เก็บ localStorage ปัจจุบันเพื่อช่วยกู้กรณีข้อมูลอ่านไม่ได้

- Reset Demo: ยืนยันก่อนแทนที่ข้อมูลปัจจุบันด้วย seed

Backup เป็นการเก็บ state ณ เวลานั้น Restore เป็นการย้อน state รวม Sign-off จึงควรพิจารณาว่าเป็นข้อมูลเก่าก่อนใช้งาน

10. การเก็บข้อมูล

แต่ละ browser/เครื่องและ path เก็บข้อมูลแยกกัน เว็บหลักกับ develop ไม่เห็นข้อมูลร่วมกัน แม้ URL อยู่โดเมนเดียวกัน ใช้ Backup/Restore หากต้องย้าย ข้อมูลอาจหายเมื่อล้าง browser หรือใช้ private mode

ใช้หนึ่ง tab ต่อ URL เพราะเวอร์ชันนี้ไม่มีการรวมข้อมูลขณะทำงานพร้อมกัน ยังไม่มี backend, login, Role, ระบบแจ้งเตือน หรือจัดการไฟล์แนบจริง

03 — GitHub, develop และ main

1. ตรวจ repository ปลายทาง

เปิด Terminal ใน repository เดิม:

git remote -v
git branch --show-current

origin ควรเป็น https://github.com/phrmthnttbn/uat-portal-management.git และ branch develop หาก origin ผิด: 

git remote set-url origin https://github.com/phrmthnttbn/uat-portal-management.git

2. ส่งเวอร์ชันใหม่เข้า develop

คัดลอก source ตามคู่มือ 01 แล้วรันทีละคำสั่ง ตรวจให้ผ่านก่อน push:

npm ci
npm run format:check
npm test
npm run build
git status
git add src index.html package.json package-lock.json tests docs public .github .prettierrc.json .prettierignore README.md BUILD-VERIFICATION.md
git diff --cached --stat
git commit -m "Complete general UAT management features"
git push -u origin develop

อย่าเพิ่ม dist หรือ node_modules ใน Git ถ้ารายการ staged มีไฟล์ส่วนตัวที่ไม่เกี่ยวข้อง ให้เอาออกก่อน commit

3. ตั้ง GitHub Pages

Repository → Settings → Pages → Source เลือก GitHub Actions

Settings → Environments → github-pages → Deployment branches and tags เลือก Selected branches and tags และอนุญาต Branch main กับ develop โดยเก็บ protection อื่นที่ทีมตั้งไว้ หากมี required reviewer ให้ผู้ดูแลอนุมัติใน Actions

ทั้ง main และ develop ต้องมี .github/workflows/deploy.yml เวอร์ชันเดียวกันใน ZIP หาก main ยังเป็นเวอร์ชันเก่า ให้คัดลอกเฉพาะ workflow นี้ผ่าน GitHub editor ใน main ก่อน ไม่จำเป็นต้อง merge ฟีเจอร์ที่ยังไม่ทดสอบ

Workflow สร้าง main ลง root และ develop ลง /develop/ แล้วรวมเป็น artifact เดียวก่อน deploy ทุก push เข้า main/develop จะสร้างทั้งสองเว็บใหม่ หาก branch ใด build ไม่ผ่าน จะยังไม่ deploy รอบนั้น

การ push develop ไม่ merge source เข้า main แต่จะ rebuild source main ปัจจุบันด้วย ดังนั้น deployment นี้เป็นการ deploy ร่วม ไม่ใช่ hosting สองชุดที่แยกอิสระ

4. ตรวจผล

Actions → Deploy main and develop → เปิดรอบล่าสุด → ทั้ง build/deploy ต้องสีเขียว

- เว็บหลัก: https://phrmthnttbn.github.io/uat-portal-management/

- เว็บทดสอบ: https://phrmthnttbn.github.io/uat-portal-management/develop/

กด Ctrl+F5 หากยังเห็นแบบเก่า เวอร์ชันใหม่มี footer v2.0

5. นำงานที่ทดสอบแล้วขึ้น main

แนะนำใช้ Pull Request บน GitHub: base main ← compare develop ตรวจ Files changed แล้ว merge หลังทดสอบผ่าน อย่า merge หาก develop มีงานอื่นที่ยังไม่พร้อม

หลัง merge ให้รอ Actions แล้วเปิดเว็บหลัก โค้ดเปลี่ยนแต่ข้อมูล localStorage ของเว็บหลักจะไม่คัดลอกจาก develop ต้อง Backup/Restore เองหากตั้งใจจะนำข้อมูลทดสอบไปด้วย

6. สั่งรันเอง

Actions → Deploy main and develop → Run workflow → เลือก develop หรือ main → Run workflow หากไม่เห็นปุ่ม ให้ตรวจว่า workflow มี workflow_dispatch และมีไฟล์บน default branch

7. แก้ปัญหา

- Branch develop is not allowed: เพิ่ม develop ในกฎ github-pages environment

- 404 เฉพาะ /develop/: ตรวจว่า main ยังใช้ workflow เก่าหรือไม่ และ Combine both websites ทำงานสำเร็จหรือไม่

- npm ci ล้มเหลว: package/lockfile ต้องตรงกัน ตรวจ logs ว่า main หรือ develop ล้มเหลว

- test ไม่ผ่าน: เปิดขั้น Test development เพื่อดูชื่อ test และ error

- Invalid username or token: ใช้ Git Credential Manager เข้าระบบผ่าน browser ด้วยบัญชีที่มีสิทธิ์ repository ไม่ใช้ password GitHub กับ Git HTTPS

- Git push rejected: git status ก่อน แล้ว pull ตามกระบวนการทีม อย่า force push เพื่อข้ามปัญหา

8. ย้อนเวอร์ชัน

Backup ข้อมูลใน browser ก่อน บน GitHub revert Pull Request ที่นำเวอร์ชันใหม่เข้า main หรือใช้ git revert ของ commit ที่ต้องการผ่าน branch/PR ตามกระบวนการทีม แล้วรอ workflow การย้อน source ไม่ได้ย้อน localStorage อัตโนมัติ

การส่งมอบครั้งนี้ไม่ได้ push หรือแก้ remote repository ให้คุณ

04 — สอนโครงสร้างและวิธีแก้โค้ดทีละส่วน

1. รู้จักไฟล์หลัก

2. เปลี่ยนชื่อเว็บไซต์และฟอนต์

เปิด index.html แก้ title และ description ลิงก์ Google Fonts โหลด Kanit จากนั้นเปิด src/style.css ค้นหา ':root' บริเวณท้ายไฟล์ที่กำหนด font-family หากเพิ่มน้ำหนักฟอนต์ใหม่ต้องเพิ่ม weight ใน URL Google Fonts ด้วย

แก้ชื่อ brand บน Sidebar ใน src/main.tsx ค้นหา className="brand" ชื่อ package อยู่ package.json หากเปลี่ยน dependencies ใช้ npm install เพื่ออัปเดต package-lock.json อย่าแก้ lockfile เอง

3. เปลี่ยนสีและระยะห่าง

เปิด src/style.css ส่วน 'Refined forest & ivory design system' เป็นธีมหลัก ส่วน 'Management screens' ใช้กับหน้าจอ v2

- .sidebar / .nav: เมนู

- .panel / .stat: การ์ด

- table / th / td: ตาราง

- .badge: ป้ายสถานะ

- @media(max-width:620px): มือถือ

ไฟล์มี CSS จากรุ่นเริ่มต้นและ override ธีมอยู่ท้ายไฟล์ ให้แก้ส่วน override ที่ตรงกับองค์ประกอบ หลีกเลี่ยงเติมกฎซ้ำหลายชุด ใช้ DevTools ตรวจ computed style เมื่อไม่แน่ใจ

4. เปลี่ยนข้อมูลเริ่มต้น

เปิด src/model.ts หา function seed() แก้ projects, scenarios, cases, results และ defects ให้ id เชื่อมกันถูกต้อง

projectId ต้องตรงกับ Project, scenarioId ของ Case ต้องเป็น Scenario ใน Project เดียวกัน, caseId ของ Result/Defect ต้องเป็น Case ของ Project เดียวกัน

seed จะใช้เมื่อยังไม่มี localStorage ของ URL นี้ การแก้ seed ไม่แทนข้อมูลที่เคยบันทึก ถ้าต้องการทดลองใหม่ให้ Backup ก่อนแล้วกด Reset Demo ใน Data & Backup

5. เข้าใจการบันทึก

ใน main.tsx:

1. storageKey รวมชื่อเวอร์ชันและ location.pathname เพื่อแยก root กับ /develop/

2. load() อ่าน localStorage แล้วเรียก validateBackup()

3. db เป็น state รวมข้อมูลทุก Project

4. scopedCases/scopedScenarios/scopedDefects กรองด้วย projectId

5. save(next) ตรวจข้อมูลและเขียน localStorage ก่อนอัปเดต state ถ้าเขียนไม่สำเร็จจะแสดงคำเตือน

6. invalidate(next, projectId) ล้าง Sign-off เฉพาะโครงการที่ข้อมูลเปลี่ยน

หากเพิ่ม mutation ที่กระทบผล UAT ต้องเรียก invalidate ก่อน save เสมอ ห้ามเปลี่ยน db โดยตรง ให้สร้าง next จาก structuredClone หรือ immutable update

6. ตัวอย่างเพิ่มช่องข้อมูล Test Case

สมมติต้องการเพิ่ม Preconditions:

1. เพิ่ม preconditions: string ใน interface Case ใน model.ts

2. เพิ่มค่าใน Case ทุกจุดของ seed()

3. เพิ่ม Field/textarea name="preconditions" ในฟอร์ม kind==='case' ของ main.tsx

4. ใน submit() ส่วน kind==='case' เพิ่ม preconditions: v('preconditions')

5. แสดงช่องนี้ในหน้าดู Case/บันทึกผล

6. เพิ่ม validation และคอลัมน์ CSV หากต้องการ Import/Export

7. เพิ่มแนวทาง migrate ข้อมูลเก่า เพราะ localStorage เดิมไม่มี field ใหม่นี้ ห้ามเพิ่ม required validation แล้วทำให้ข้อมูลเก่าอ่านไม่ได้โดยไม่เตรียม migration

8. เพิ่ม test ที่ตรวจค่าถูกเก็บและส่งออก

9. รัน npm run format, npm test และ npm run build

7. CSV และ Backup

parseCsv รองรับ quoted field, comma, newline และ BOM ส่วน importCsv ตรวจหัวตาราง รหัสซ้ำ ความสัมพันธ์ และ Priority ก่อนคืน Database ใหม่ กรณี error state เดิมไม่ถูกแก้

validateBackup ตรวจ version, types, ค่า enum, ID และความสัมพันธ์ระหว่างข้อมูล ใช้ทั้งตอน load, save และ Restore หากเพิ่ม entity ใหม่ต้องแก้ schema, validation, backup และ tests ให้พร้อมกัน

8. วิธีตรวจทุกครั้งหลังแก้

npm run format
npm run format:check
npm test
npm run build
npm run dev

npm test ใช้ Node test runner และ transpile model.ts ด้วย TypeScript ที่ติดตั้งในโปรเจกต์ ไม่ใช่ browser test การผ่าน test จึงยังต้องลองฟอร์มจริงตาม acceptance checklist

9. ต่อฐานข้อมูลภายหลัง

แยก save/load ออกเป็น data service แล้วค่อยเปลี่ยนเป็น API รักษา projectId และ foreign keys ในทุก entity การใช้งานร่วมกันต้องมี transaction/version conflict handling และสำรองข้อมูลที่ server ก่อนเพิ่ม Role ในภายหลัง

05 — รายการทดลองรับมอบใน Browser

เอกสารนี้เป็นรายการให้ผู้รับมอบทดลอง ไม่ได้หมายความว่ารายการ UI ทั้งหมดถูกตรวจอัตโนมัติแล้ว ผลตรวจจริงอยู่ BUILD-VERIFICATION.md

เตรียม

1. npm ci → npm test → npm run build → npm run dev

2. เปิด browser ที่อนุญาต localStorage และเปิดเพียงหนึ่ง tab ของ URL นี้

3. Backup ก่อน Reset Demo เพื่อไม่ให้กระทบข้อมูลที่ต้องเก็บ
